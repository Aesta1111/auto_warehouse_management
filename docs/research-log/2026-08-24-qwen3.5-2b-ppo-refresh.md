## Method

The active prompt was moved to a YAML metadata file plus a byte-addressed TXT
template. The template contains explicit live-state and directive markers, clear
JSON requirements, and three diverse examples for each of the four directive
classes. Exact template bytes and metadata are included in the prompt contract
digest.

The PPO model was versioned to exactly four hidden layers of 256 units. Parent
training is configured for 100,000 timesteps and requires CUDA; frozen-LLM PPO
adaptation is configured for 4,096 environment steps. Manifests now record CUDA
availability, GPU name, Torch build, and selected device. The active output
directories are versioned so historical checkpoints cannot be overwritten.

The pinned Q8 GGUF was downloaded outside Git and hashed. The local server was
started with the 8k context and full permitted model offload. A health request,
model identity check, strict JSON-schema request, and a request built from the
real `LlmPromptBuilder` template were sent before stopping the server. The
live request used a wrapper state from matched-demo seed `9300`; reasoning was
explicitly disabled throughout.

## Results

- `uv lock` and `uv sync --all-groups` completed with Torch `2.8.0+cu128` from
  the CUDA 12.8 PyTorch index.
- The downloaded GGUF size was `2,080,140,384` bytes and its SHA-256 matched the
  pinned digest exactly.
- The server reported `status: ok`, advertised the pinned Qwen model identity,
  loaded the model with context `8192`, and permitted full configured offload.
- The raw strict-schema request returned valid JSON. The real prompt request
  parsed successfully as `LlmActionResponse`; observed latency was approximately
  `1.546 s` for that request.
- The CUDA smoke test completed finite forward and backward passes on `cuda:0`.
- No parent checkpoint, four-class preflight report, matched demo, adaptation
  checkpoint, confirmation gate, or final comparison was produced yet.

## Observations

- The server log reported unused `blk.24.*` tensor warnings while loading the
  candidate GGUF. The model nevertheless loaded and served the strict request;
  this warning is retained for follow-up rather than hidden or used to justify
  a silent model substitution.
- The initial `w-ahmad/Qwen3.5-2B-GGUF` metadata request was unauthorized, so
  the Apache-labeled `bartowski/Qwen_Qwen3.5-2B-GGUF` candidate was selected and
  pinned instead. Compatibility failure of this selected artifact remains a
  stop-for-review condition.

## Interpretation

The selected artifact is compatible with the local server, strict structured
output, the external prompt contract, and the target GPU smoke test. This is a
runtime readiness result only. It does not establish directive sensitivity,
four-class preflight coverage, PPO learning, adaptation benefit, or any result
relative to the historical run.

## Decision

Proceed with the pinned Qwen artifact and the versioned 4x256/CUDA configs. Keep
reasoning disabled and keep the final seed `9200` untouched until confirmation
passes. Do not change models or quantization silently, and do not edit the prior
full-run research-log conclusion.
